# CONFIGURATION

> Every setting, what it defaults to, and the command line. There is no configuration you are
> required to write: `docucane ./docs` renders a folder as it stands. A config file exists
> so a project can settle its answers once.

---

## 1. The config file

`docs.config.json`, at the root of the project. The builder looks for it beside the documents and
then upwards, so it can sit at the top of a repository whose documents are three folders down.
`.docucane.json` is accepted as an alternative name.

```json
{
  "title": "Acme Docs",
  "docs": "documentation",
  "out": ".docucane",
  "groupOrder": ["Documents", "Audits", "Schema"],
  "diagrams": { "engine": "clean" }
}
```

Everything is optional. Anything absent takes the default in the table below.

## 2. Settings

| Key | Default | What it does |
|---|---|---|
| `title` | the project folder's name + " Docs" | Sidebar heading, browser tab, and the key the reader's browser stores state under. |
| `docs` | `"docs"` | The documents folder, relative to the project root. |
| `out` | `".docucane"` | Where the page is written. Add it to `.gitignore`. |
| `extensions` | `[".md", ".markdown"]` | What counts as a document to render. |
| `verbatim` | see [File types](#file-types) | Extensions shown as-is in a code block, and the group each lands in. |
| `rootGroup` | `"Documents"` | The sidebar heading for files sitting in the folder itself. |
| `groupOrder` | `[]` | Fixes the order of groups; anything unlisted follows alphabetically. |
| `diagrams.engine` | `"clean"` | `clean` or `mermaid` — see [Diagrams](#diagrams). |
| `diagrams.nodeTextWidth` | `210` | Pixels a box's text runs before it wraps. |
| `diagrams.edgeTextWidth` | `200` | The same for an edge label. |
| `comments` | `true` | The margin comments feature. `false` removes it from the page entirely. |
| `search` | `true` | The sidebar search box. |

### <a id="groups"></a>2.1 Groups

Groups are derived, not declared: the documents folder itself is one group (named by `rootGroup`),
and every sub-folder is another named after itself, title-cased. `groupOrder` only sets the order:

```json
{ "groupOrder": ["Documents", "Audits"] }
```

A group that appears in `groupOrder` but has no folder is simply ignored.

### <a id="file-types"></a>2.2 File types

`extensions` are rendered as Markdown. `verbatim` maps an extension to the group its files land in,
and those files are shown as a code block rather than parsed:

```json
{
  "verbatim": {
    ".dbml": "Schema",
    ".sql":  "Schema",
    ".csv":  "Data"
  }
}
```

The default covers `.dbml`, `.dbdiagram`, `.sql`, `.json`, `.yaml`, `.yml`, `.tsv` and `.csv`.
Anything not in either list is skipped.

### <a id="diagrams"></a>2.3 Diagrams

`"engine": "clean"` re-lays flowcharts out with ELK; `"mermaid"` uses mermaid's own layout for
everything. This only sets the *default* — both engines are always in the page, and the reader can
switch any single diagram from the button in its corner. See [Diagrams](./2.%20DIAGRAMS.md).

## 3. The command line

```
docucane [folder] [options]
docucane init [folder] [--docs <dir>] [--title <name>] [--force]
```

| Option | Effect |
|---|---|
| `folder` | Render this folder, ignoring the configured `docs`. |
| `--out <dir>` | Write the page somewhere else. |
| `--config <file>` | Use this config file instead of searching. |
| `--title <name>` | Override the title for this build. |
| `--engine clean\|mermaid` | Override the default flowchart engine. |
| `--no-open` | Build without launching a browser. |
| `--refresh` | Re-download mermaid, ELK and the font instead of using the cache. |
| `-h`, `--help` | Usage. |

## 4. What a build writes

```
.docucane/
  index.html              the whole dashboard, self-contained
  vendor/
    mermaid.min.js        pinned version, cached after the first build
    elk.bundled.js        pinned version, cached after the first build
    inter.css             the font, base64, cached after the first build
```

`index.html` references the two scripts beside it and carries the font inside it — a `file://`
origin will not fetch a font over CORS even from the folder next door, but it will load a script.

Nothing outside the output folder is ever written, and no source file is ever modified.

## 5. Offline and failure behaviour

The first build needs the network once, to fetch the three vendored assets. Every build after that
is offline. If a fetch fails the build still succeeds, with a reduced page:

| What failed | What you see | What the page loses |
|---|---|---|
| mermaid | `mermaid: CDN fallback` | Nothing, but the page now needs a network connection to draw diagrams. |
| ELK | `elk: unavailable` | Flowcharts fall back to mermaid's layout. |
| the font | `font: system fallback` | Inter; the page uses a system typeface. |

Run `--refresh` once you have a connection to fill the cache in.

## <a id="init"></a>6. Wiring a project up

```bash
npx docucane init
```

Writes `docs.config.json`, creates the documents folder if it is missing, appends `.docucane/`
to `.gitignore`, and installs three things into the project's `.claude/`:

| Installed | What it is for |
|---|---|
| `commands/docs.md` | `/docs` — render the dashboard and open it. |
| `skills/write-doc/` | How to write a document in this house style. |
| `skills/audit-docs/` | A read-only audit of the documents, as a structured report. |

Nothing already present is overwritten unless you pass `--force`; anything skipped is listed.
